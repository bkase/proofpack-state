## Metal execution is real, not a silent CPU fallback

`bend x.bend -o x` with a `!` call emits `x.gpu` beside the binary:

```
x.gpu: [air64:MetalLib executable (MacOS), version 1.2.9]
       [applegpu:Mach-O 64-bit GPU executable applegpu]
```

Deleting `x.gpu` and re-running prints
`bend: compiling the GPU program (… is missing or stale)`, so the file is
consulted at run time rather than baked in. `--gpu off` forces `!` onto the
CPU pool, which is how every CPU/Metal comparison below was taken.

## How U32 is represented, and why that matters for the proofs

Base declares `type U32 is Data: U32{data: Word(32n)}` and `Word(n)` is a
little-endian vector of `Bool`. So the **checker** sees every `U32` operation
as a bit-vector function it can do induction over — `U32.and` *is*
`Word.and(32n, ..)`. Meanwhile the compiler's `OPERATIONS` table lowers
`U32.and`/`U32.shr`/`U32.add`/… to single native machine ops (`U32_BIN(a, &,
b)` in C, the same source compiled by Metal for the device).

This is the single most important fact for this project: **law `B-01` can be
proved by structural induction over 32 bits, while the production hot loop
still runs one machine instruction per operation.** The `Word(32n)` vector
never materializes at run time, because a `match` on a `U32` only appears in
erased proof code. The lowering itself is trusted (see `TRUST.md`).

## The substrate experiment (SPEC 7.5)

`bench/spike_t01.bend` runs the fused kernel this product is built on —
`popcount(required AND NOT have)` over dense `U32` word tiles — in two shapes,
on the CPU pool and on Metal, over identical leaf code:

* **owned** — each leaf builds its own tile-local word lists.
* **shared** — one host-built pair of word lists is handed to every leaf.

2^16 leaves x 128 words = 8,388,608 words = 268,435,456 bits per trial.

| Trial | Metal enabled | `--gpu off` |
|---|---|---|
| `owned.cpu` | 94, 80, 87, 70 ms | 15, 19, 15, 15 ms |
| `owned.gpu` | 84, 17 ms | 17, 21 ms |
| `shared.cpu` | 186, 327 ms | 178, 185 ms |
| `shared.gpu` | 9, 18 ms | 176, 176 ms |

Raw output: `T01-spike-gpu-on.txt`, `T01-spike-gpu-off.txt`.

### Results agree across backends

Every trial returns the same two sums (`68952480` for `owned`, `74383360` for
`shared`) on the CPU pool and on Metal. That is the M0 "CPU/Metal equality"
evidence, on real dispatches.

### The 10x finding: do not share operand words down a fork tree

`shared` costs ~12x `owned` on the CPU pool (178 ms against 15 ms). The
emitted C says exactly why. `Spike.fused` and `Spike.popcount.go` compile to
flat native tail loops (`spin_3`, `spin_1`) with **zero** `term_keep`,
`ctr_take` or `rfc_seal` — they only match their lists, so the compiler
borrows them (`T01-flat-loops.c.txt`). The reference-count traffic is in the
*fork node*:

```c
_req_0 = term_keep(e, _req_0, 1);
_inv_0 = term_keep(e, _inv_0, 1);
```

(`T01-shared-node.c.txt`) — one atomic per operand per fork level, paid on the
way down to all 65,536 leaves. This is `SHADERS.md`'s "a `+` value read by
every lane costs an atomic per read", measured on this workload.

### The decision SPEC 7.5 asks for

**No new runtime or compiler primitive is needed for v0.1.** The proposed
`FrozenWords` / `ReadSpan` / `OwnedTile` intrinsics are *not* being pursued.
The cost the experiment found is not a missing storage API — it is a plan
shape. The fix is in the planner, not the language:

> A leaf job owns the words it reads. The plan carries each tile's operand
> words to exactly one leaf, and the fork tree splits data rather than
> broadcasting it.

`execute/` is built to that rule, and `bench/` keeps this spike as the
regression that detects a planner change which starts broadcasting again.

Secondary observation, not yet a claim: with Metal enabled the *shared* shape
is much faster on the device (9–18 ms) than on the CPU pool (176 ms), and the
`owned.cpu` trials are slower in a process that has initialised the GPU heap
(70–94 ms against 15–19 ms). Both are single-process observations at one size;
§11.3's interleaved trials, not these numbers, are what a performance claim
would have to rest on.
